# Multi-language, anti-cheat, AI coach and problem bank

## 1. Multi-language judging (C++, Python, Java, JavaScript)

* One registry (`backend/src/services/executor/languages.js`) drives the judge, validation, the
  `/api/problems/languages` endpoint and the editor's language picker.
* Test cases did **not** change: every language reads the same stdin format and prints the same output format
  (`wrappers.js` for Python/JS/Java, `code-generator.js` for C++).
* Starter code for every language is generated from `judgeConfig` (`starter-generator.js`), so existing problems work
  immediately. An optional `starterCodes.{cpp,python,javascript,java}` on a problem overrides the generated one.
* New supported parameter/return type: `vector<vector<int>>` (grids, matrices) in all four languages.
* Collaborative battle rooms support C++, Python, JavaScript and Java. Each room/team/problem/language has a separate durable Yjs document, local backup and analytics identity. Teammates selecting the same language edit together.
* Docker is required by default; missing Docker or a missing runner image fails closed.
  Explicit development-only direct mode uses a scrubbed environment (server secrets such as
  `JWT_SECRET`/`MONGO_URI` are not visible to submitted code), process-group kill on timeout, capped output and
  `ulimit` file/memory limits. **It is still not a real sandbox** - use Docker mode for anything public:
  `docker build -t codeforge-runner:2.0 backend/src/services/executor/docker`
  (override the tag with `RUNNER_IMAGE`; development-only direct mode with `FORCE_DIRECT_EXECUTION=true`
  requires a POSIX host and is rejected in production). The Docker CLI also works from Windows.
* Fixed an existing bug: C++ `vector<string>` return values produced invalid generated code.

## 2. Anti-cheat

The colleague's original legacy 1v1 battle penalties are restored, as requested:
large paste, large insertion, unexplained code growth and sufficiently long
focus/tab absences can award strikes. The default third strike forfeits the
legacy battle under the original rules. Existing threshold environment options
and explicit monitor mode remain available. Clipboard contents are not stored or
transmitted, and paste/copy events outside the editor are ignored.

Contests remain record-only. Collaborative team-room behavioural analytics remain
separate from legacy battle penalties: this update does not introduce team
forfeits or team scoring rules. Browser interaction signals can be bypassed and
are not reliable proof of cheating.

## 3. AI post-battle review and long-term coach

```
battle ends -> metrics (deterministic) -> rule-based draft -> LLM refines (optional) -> saved -> "analysis_ready"
```
* `GET /api/battles/:id/analysis` - the review (generated on demand if needed). `GET /api/coach/me` - patterns across
  your last 20 analysed battles plus practice submissions (weak tags, habits).
* The LLM never computes anything: it receives the metrics and a rule-based draft and may only reword/prioritise. Its
  output is validated and coerced; on any failure (no key, timeout, bad JSON) the rule-based review is saved instead,
  so the feature works with **no API key at all**.
* Configure with env vars (no SDK): `LLM_PROVIDER=anthropic|openai` (`openai` = any OpenAI-compatible API: OpenAI, Groq,
  OpenRouter, Gemini's OpenAI endpoint, Ollama), `LLM_API_KEY`, `LLM_MODEL`, optional `LLM_BASE_URL`, `LLM_TIMEOUT_MS`.
* Privacy: only metrics are sent. The player's last submitted code is sent **only** if `LLM_INCLUDE_CODE=true`.
  Stored behaviour data is sizes and timestamps - never keystrokes or code samples.

## 4. Problem bank

`npm run verify:problems` runs every reference C++ solution through the real judge against expected outputs
generated by an independent JavaScript implementation (no database needed). `npm run seed:problems` verifies, then
inserts the 31 problems (12 easy / 14 medium / 5 hard) that do not exist yet; existing problems are never touched.

## Tests

`cd backend && npm run test:unit` (needs `g++`, `python3`, `node`; Java tests use `javac` or the JDK compiler module and
skip when no toolchain exists). `cd frontend && npm test`.
